# PCBS shadow-store metadata and planning research

Status: READY FOR REVIEW. Source investigation reviewed independently for the SQL-statistics/physical-storage boundary and prototype field preservation. No implementation or production policy selected.

Cache metadata **is used for planning**. Replacing an encoded PCBS payload with an ID must not replace its SQL-facing size with the ID's heap or serialized size. Spark separately accounts for the physical objects/bytes in its block stores. Those two size domains already differ and must remain distinguishable.

The short-term constraint is existing, unmodified Spark. A Spark change is a last resort with the user's estimated 4–5 year broad-rollout horizon. This research does not authorize an interface, configuration or default change. Current Spark/PCBS behavior is treated as RELEASED. Proposed shadow metadata is unimplemented.

## What returns to the driver

Spark 3.5.5 CachedRDDBuilder creates driver LongAccumulators for size, rows and materialized partitions. Its persisted statistics wrapper adds each CachedBatch.sizeInBytes and numRows while producing cache records; a task completion listener increments materializedPartitions only when the task is neither failed nor interrupted. Sources: [InMemoryRelation.scala:213](https://github.com/apache/spark/blob/v3.5.5/sql/core/src/main/scala/org/apache/spark/sql/execution/columnar/InMemoryRelation.scala#L213), [wrapper:281](https://github.com/apache/spark/blob/v3.5.5/sql/core/src/main/scala/org/apache/spark/sql/execution/columnar/InMemoryRelation.scala#L281).

These accumulator updates travel with task results: Task.collectAccumulatorUpdates selects external accumulators, Executor packages updates into DirectTaskResult, and DAGScheduler finds the matching driver accumulator by ID and merges its update. Result-task updates have completion deduplication; failed-task collection filters external accumulators according to countFailedValues. This is Spark's existing accumulator protocol, not a new exactly-once payload-registration protocol. Sources: [Task.scala:207](https://github.com/apache/spark/blob/v3.5.5/core/src/main/scala/org/apache/spark/scheduler/Task.scala#L207), [Executor.scala:704](https://github.com/apache/spark/blob/v3.5.5/core/src/main/scala/org/apache/spark/executor/Executor.scala#L704), [merge:1681](https://github.com/apache/spark/blob/v3.5.5/core/src/main/scala/org/apache/spark/scheduler/DAGScheduler.scala#L1681), [completion:1824](https://github.com/apache/spark/blob/v3.5.5/core/src/main/scala/org/apache/spark/scheduler/DAGScheduler.scala#L1824).

The driver receives aggregate row/size/materialization updates through this path; it does not automatically receive every Parquet footer, batch object or per-column batch-statistics row. Separately, BlockManager reports partition-block locations, tiers and physical memory/disk sizes.

## Why preserving values is necessary but not a complete plan-equivalence proof

CacheManager.useCachedData replaces matching logical fragments with cachedRepresentation.withOutput and preserves query hints (:301–319). InMemoryRelation.computeStats returns original plan statistics before full materialization and replaces rows/size afterward (:416–424). LogicalPlanStats caches statistics when first requested; AQE explicitly invalidates and re-optimizes them. Consequently, planning depends on configuration, query shape and when materialization/statistics become available.

A shadow representation must preserve the existing values **and** their materialization/update semantics. Smaller physical metadata can change Spark cache residence and execution timing. No source-only review proves all resulting plans remain identical. Plan equivalence remains a future verification requirement, including pre-/partially-/fully-materialized caches, CBO/broadcast/AQE, CPU/GPU/fallback and count/zero-column routes. This is a requirement for review, not authorization to run another experiment or change production defaults.

PCBS also uses sizeInBytes==0 to recognize a zero-column encoded batch, and numRows to construct rows-only output on CPU and GPU. GPU decode otherwise passes sizeInBytes as the Parquet input length. These execution semantics must survive any reference representation; positive ID serialization overhead must not turn an empty payload into a nonempty Parquet file. Source: PCBS:439–460,667–675,899–909.

Spark's physical size estimation is separate: SizeEstimator:219–225 recognizes its internal KnownSizeEstimation interface or traverses object fields. Merely implementing CachedBatch.sizeInBytes does not make that value the physical heap estimate. This observation does not select a new accounting policy or recommend changing a Spark API.
