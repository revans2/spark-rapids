# Real-world cache research harness

This experiment is unreleased. It preserves production Spark/plugin behavior and adds no public configuration. All project operations use MCP docker_exec. The frozen earlier fixtures and datasets remain unchanged.

Compile WorldCacheBench.scala with build_bench.py using --spark and a fresh --out directory. The build uses Spark's assembly jars and records the expanded command and source/artifact SHA-256. It does not run GPU work.

Main: org.apache.spark.sql.pcbsworld.WorldCacheBench. Arguments: MODE INPUT_MANIFEST ORACLE_JSON. MODE is oracle, cpu-default, pcbs-java, rg-java or rg-codec. WORLD_CACHE_STORAGE_LEVEL selects DISK_ONLY or MEMORY_AND_DISK for cache modes. The launcher owns immutable executor/heap/plugin/serialization/resource controls. Every arm and oracle uses UTC with spark.sql.parquet.inferTimestampNTZ.enabled=false, as explicitly selected for this experiment; effective Spark schema and the read configuration are recorded. No casts or source-file changes are introduced. Oracle and cpu-default reject an initialized RAPIDS SQLPlugin. GPU cache modes reject a CPU InMemoryTableScan fallback.

The input manifest contains dataset_id, partitions=16, total_rows and ordered files entries with partition, path, rows and bytes. Partitions may have different row counts. Each input file is read once and coalesced to one partition before union; there is no SQL repartition/shuffle or row duplication. Input footer rows and file sizes are checked before timing. Additional manifest provenance remains available to the launcher/verifier.

Run oracle in a fresh CPU JVM before cache experiments. It reads the canonical input uncached and writes a new ORACLE_JSON (never overwrites). Every cache read uses the same all-column aggregation and compares exact rows, four salted xxhash64 limb sums, per-column null counts and raw-value bytes with this external oracle. For each hash the seed salt is followed by interleaved column position, isNull and field value. Unsigned low/high 32-bit limbs are summed separately; the manifest row bound prevents Long overflow. These checks are probabilistic fingerprints, not a mathematical proof of row equality, and do not test row ordering.

Raw-value bytes mean nonnull scalar values at their fixed physical width plus actual UTF8 string octets. Offsets, validity masks, allocator padding and intermediates are excluded. This denominator is separate from observed producer/decode GPU bytes and uncompressed Parquet encoded-page sizes. Supported initial schemas are flat boolean/integer/float/double/date/timestamp/string; nested and decimal schemas fail explicitly.

Output lines begin WORLD_CACHE followed by one JSON object. Events include config, canonical_file, cache_plan, phase_start, phase, partition, codec, storage, operator, scan, query_plan, read, unpersist and complete. Oracle payload fields are rows, hash_sums (13-low/high then97-low/high), null_counts, value_bytes, raw_value_bytes, schema_json and raw_value_bytes_definition. Arrays follow schema field order. Read0 is warmup; reads1–3 are measured. Fill is an explicit cached-record traversal. Heap sampling and GC MXBean deltas follow the earlier fixture; observed peaks include garbage and are not minimum required memory.

Every operator event records metrics and accumulator IDs. Each cached query requires a single full-column cache scan and matching numOutputRows. GPU arms additionally require GPU aggregate operators and an entirely GPU path below the first reduction, covering full-row projection/coalescing/conversion; final tiny-row collection may convert to rows. The executed plan is emitted before a rejected GPU path fails. The CPU/default-cache arm never loads the PCBS observer. GPU arms emit process-local cumulative observer snapshots; row-group arms use the row-group observer. Successful top-level decode counters do not prove absence of internal cuDF/RMM retries.

Storage checkpoints inspect all16 local RDDBlockIds without reading payloads. memory_bytes/disk_bytes/cached_partitions are local authoritative observations; disk_file_bytes measures actual local serialized cache files. Per-block local_blocks are retained. async_rdd_* reports Spark RDDStorageInfo separately because driver status updates can lag. Blocking unpersist must remove every local status and disk file and its driver RDDStorageInfo entry.

No benchmark, GPU execution, real-data oracle or large-input rewrite is started by the build script. The coordinator owns admission, result verification and experiment sequencing.
